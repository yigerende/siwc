# SIWC 工具检索兼容

账号管理顶部提供独立的「SIWC 工具检索兼容」开关，默认关闭。管理员通过 `GET/PUT /api/v1/admin/siwc/tool-search` 读取/保存 `{ "enabled": false }`，持久键为 `siwc_tool_search_compat_enabled`。设置读取缓存60秒，当前进程保存立即生效；保存失败不更改缓存。

## 触发范围

第一次发送完全沿用原请求构造、插件和上游线路，不预先转换。以下条件全部满足才允许一次兼容重试：

- 实际选中 SIWC 账号、开关开启。
- 上游 HTTP400，`error.code=subscription_sharing_unsupported_capability`，`error.param=input`。
- 请求 `input` 的顶层记录包含 `tool_search_call`。
- 客户端尚未收到输出、请求未取消、此请求尚未消耗兼容重试预算。

HTTP200中的流式错误、网络异常、429/502、图片错误、上下文过长、none以及其他400均不触发本兼容逻辑。只有 `tool_search_output` 不触发。普通 OAuth/API Key 不进入该分支；关闭后保留原错误和原处理行为。

## 请求及响应

在原账号和原代理的同一个传输回调内重试，复制原请求的URL、认证头、会话头、模型、完整历史、图片/文件、压缩项及参数。只转换工具检索协议：声明转换为普通函数，调用及配对结果转换为函数调用/结果，发现的工具增加到有效声明中。原生自定义工具及命名空间保持原生格式，不采用通用工具适配器的全面降级。

原始请求体保持不变；JSON数字保持精度。结果恢复为客户端期望的 `tool_search_call`、`execution=client`、对象参数与一致的call_id/item_id。命名空间中的同名函数不被误改。流式恢复按需读取，保留终态用量、非相关事件、错误和压缩结果，关闭流会关闭上游。

所有账号尝试共享单次兼容预算，其他重试循环不会重置它。WebSocket→HTTP桥接每个response.create单独限一次；普通OAuth的WebSocket路径不变。首个明确拒绝不进入成功结算，最终响应沿用原有用量提取和结算链路。此兼容逻辑不回放客户端本地工具执行。

## 运维与限制

脱敏日志 `siwc_tool_search_compat_retry` 表示使用唯一一次兼容机会；`siwc_tool_search_compat_retry_accepted` 仅表示重试收到HTTP2xx，不代表已完成流式响应，最终成功以原有用量/终态日志为准。日志不输出提示词、工具参数、令牌或附件。

若后续每轮仍携带同一检索历史，每轮会先失败一次再转换重试；不建立跨请求自动启用状态。原型实测额外等待约1.1～3.1秒，仅为样本。重试转换遇到同名歧义、缺失配对字段或无效格式时保留原错误，不擅自删除用户数据。

测试覆盖设置持久化、失败回读、并发缓存、开关双状态、普通OAuth隔离、精确错误识别、单次预算、已输出/已取消、原请求及headers保留、原生工具/命名空间、协议还原、流式异常/Close、大数字、并发隔离和原生压缩组合。正式真实测试结果记录在运维归档，不包含客户会话内容或凭据。
