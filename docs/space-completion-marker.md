# SIWC 全自动完成标记

Space 当前最后一步（空间合并、合并2.0、删除账户、API 商户）的页面状态为 `completed` 即同步标记。使用 `ProStages` 和最后应用的手动修正投影；不再检查 OAI、到账或商户 retired_at。手动全自动、自动补货和单步操作最终更新同一账号资料，走同一规则。

## 传递与显示

- SIWC 账号名称下显示绿色“Space 已完成”；可展开最后一步、时间、订单和手动确认说明。标记不代表退款到账。
- Space 全自动列下显示标记同步状态，失败时有“重试标记”，只重新排期标记任务，不重跑登录、付款或最后一步。
- 管理员接口 `PUT /api/v1/admin/accounts/:id/space-workflow`：source_id、全局递增 revision、email、flow_id、order_id、stage、completed、manual、changed_at。目标账号必须为邮箱匹配的 SIWC 账号。
- 使用原推送绑定及加密连接，拒绝写入不匹配的下游。切换全局推送设置不改变旧账号归属。

## 异步、顺序与恢复

SQLite INSERT/UPDATE 触发器和原账号更新同事务写入 `pro_siwc_markers`；只比较影响最终显示和绑定的字段，额度轮询/费用刷新不入队。不扫描所有历史账号，不做历史回填。每个邮箱只保存最新待同步状态。

独立后台 worker 每2秒领取最多2项，逐项网络超时8秒、租约45秒。数据库短事务结束后才联网，独立管理员HTTP客户端避免与额度查询共用登录锁。失败间隔5、15、30、60、300秒，随后每300秒继续；仅影响标记状态，不消耗业务重试次数。

source_id 和递增版本持久化。SIWC 按原子版本条件更新，拒绝跨来源覆盖和同版本不同内容，旧回执不能覆盖本地新任务。每次新版本必须真正发送，不能因内容曾同步过就跳过，以防中途旧请求晚到。新流程/重试恢复未完成时发送 `completed=false`，清除当前标签。

任务保留资料快照，完成后删除本地账号仍可送达已排队的标记。前端列表每页一次批量读本地同步状态，不逐号访问 SIWC。失败摘要不返回上游正文和凭据。

## SIWC 可选自动删除

账号管理顶部设置默认关闭，默认保留60分钟、每5分钟清理，可改保留0～43200分钟、间隔1～1440分钟。0表示下个清理周期即可删除。每轮最多100个，按收到完成标记的时间计时；同一流程重复同步不延长，取消完成标记后退出清理范围，新流程重新计时。

只软删除仍匹配 SIWC 身份/邮箱且完成标记到期的账号；组成员和定时测试一起清理、调度缓存失效。历史使用/计费记录、Space账号/订单/卡台均保留。配置、标记、账号与删除在事务中复核并加锁，多实例通过事务锁和持久化轮次防重复；清理失败回滚并在后台重试。

## 发布与验证

先发布 SIWC 接口和数据表，再发布 Space 发送端。使用两个隔离工作区，不覆盖另一会话已发布的远程压缩功能。升级不自动开启清理、不补标历史账号。回滚应用时保留新增表与配置，不能用旧库覆盖持续产生的数据；回滚 Space 之前须移除本次两个 SQLite 触发器，以免旧版本继续堆积任务。

回归覆盖四类完成投影、手动修正、普通未完成状态、原目标绑定、远端失败不改订单、事务回滚、额度轮询不入队、重启/删除/并发领取、乱序版本、同版本冲突、批量列表/ETag、界面重试、真实临时 PostgreSQL 的清理竞态与账本保留。所有测试使用临时库/模拟网络，不执行正式业务。
